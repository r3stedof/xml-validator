# XML Validator

Русскоязычный клиентский инструмент для проверки синтаксиса XML. React + TypeScript + Vite, CodeMirror 6, `@xmldom/xmldom`, Vitest.

## Возможности
- Проверка настоящим XML-парсером в браузере, без сервера и передачи документов.
- Редактор с подсветкой синтаксиса, нумерацией строк, копированием и форматированием.
- Загрузка файла перетаскиванием или через диалог, UTF-8 и BOM-маркированный UTF-16.
- Настраиваемый лимит файла (1–20 МБ), отчёт JSON, скачивание XML, история результатов текущей сессии.
- Светлая/тёмная тема, адаптивная вёрстка.

## Запуск и проверка
Требуется Node.js 20.19+ или 22.12+.

```bash
npm install
npm test
npm run build
npm run dev
```

## Публикация на Vercel
1. Создайте Git-репозиторий и загрузите туда содержимое этой папки (не `node_modules` и не `dist`).
2. Войдите в официальный интерфейс Vercel и импортируйте репозиторий.
3. Framework preset: Vite; Build command: `npm run build`; Output directory: `dist`.
4. Нажмите Deploy. Vercel выдаст фактический публичный HTTPS URL.

Альтернатива — Netlify: импортируйте репозиторий; настройки сборки уже заданы в `netlify.toml`.

## Безопасность и ограничения
- Парсер запускается локально; пользовательский XML не отправляется на сервер.
- Не настроен resolver внешних сущностей, внешние ресурсы не загружаются намеренно. Набор XML-парсеров имеет различия в диагностике, поэтому номер строки/столбца показывается только когда доступен достоверный locator; текущая версия `@xmldom/xmldom` часто не отдаёт позицию через legacy error callback, и тогда интерфейс честно указывает, что координаты недоступны.
- Лимит размера снижает риск чрезмерного расхода памяти, но не является полноценной песочницей для всех враждебных входных данных.
- Проверяется синтаксис, а не соответствие XSD, DTD-схеме или бизнес-правилам.
- Внешние шрифты и аналитика не используются; CSP запрещает загрузку скриптов и соединений с посторонними источниками.
